## 2. Назначение и границы системы

### 2.1. Цель разработки
Автоматизация выявления коллизий между проектными спецификациями (ВОР) и локальными сметами (ЛСР) с углубленным анализом внутренних инженерных систем (электроснабжение, слаботочные системы, автоматика). 

### 2.2. Границы ответственности модуля (ЭОМ и СС)
* **Входит в скоуп:**
  * Сопоставление кабельной продукции с учетом жильности, сечения и типа изоляции (ВВГнг-LS, UTP, FTP).
  * Валидация кратных измерителей специфичных для электромонтажа («100 м», «1000 м», «100 шт»).
  * Разделение оборудования и материалов, заложенных в расценке (гофротруба, крепеж, клеммники).
* **Не входит в скоуп:**
  * Электротехнические расчеты (токи короткого замыкания, падение напряжения).
  * Чтение однолинейных схем (только табличные кабельные журналы и спецификации).

## 3. Архитектура 5-фазного конвейера ETL

~~~text
[Фаза 1: Ingestion & Topology Extraction]
  ├── openpyxl -> ЛСР (421/пр) и ВОР (Excel)
  └── pdfplumber -> Спецификации оборудования и кабельные журналы (PDF)
                        │
                        ▼
[Фаза 2: Normalization & Canonicalization]
  ├── Топологическая привязка (CellPointer)
  ├── MEP Лексическая чистка (ABBREVIATIONS_MAP_MEP, CONSTRUCTION_STOP_WORDS)
  └── Канонизация инженерных размерностей (м, км, шт, компл) в Decimal
                        │
                        ▼
[Фаза 3: Intermediate Checkpoint (SQLite)]
  └── Таблица audit_staging (Human-in-the-Loop аудит промежуточных распарсенных строк)
                        │
                        ▼
[Фаза 4: Gated Hybrid Matching Engine]
  ├── Unit Gating (I_unit) -> запрет сравнения кабеля (м) и лотков (шт)
  ├── Dimensional Lock (I_dim) -> проверка сечений (например, 3х1.5 vs 3х2.5)
  └── Скоринг: w1*Code + w2*Fuzzy + w3*Context
                        │
                        ▼
[Фаза 5: Collision Analysis & Reporting]
  ├── Анализ запаса кабеля (Cable Slack Tolerance)
  └── Экспорт DiscrepancyReportItem (JSON / Excel)
~~~

## 4. Схемы данных (Pydantic v2 Models)

~~~python
from decimal import Decimal
from typing import Literal, Optional
from pydantic import BaseModel, ConfigDict, Field, field_validator, model_validator

class CellPointer(BaseModel):
    """Топологический указатель источника данных."""
    model_config = ConfigDict(frozen=True)
    doc_type: Literal["SPECIFICATION", "VOR", "LSR", "SSR"]
    file_name: str
    sheet_name: str
    row_idx: int = Field(..., ge=1)
    coordinate: str

class AuditLineItem(BaseModel):
    """Канонизированная строка строительной ведомости/сметы."""
    model_config = ConfigDict(arbitrary_types_allowed=True)
    pointer: CellPointer
    item_code: Optional[str] = Field(None, description="Шифр расценки или артикул")
    raw_title: str
    clean_title: str
    
    quantity: Decimal
    raw_unit: str
    canonical_unit: str
    unit_multiplier: Decimal = Field(default=Decimal("1.0"))
    base_price: Optional[Decimal] = None

    @field_validator("quantity", "unit_multiplier", "base_price", mode="before")
    @classmethod
    def parse_strict_decimal(cls, value: object) -> Optional[Decimal]:
        """Защита от неявного приведения через float для сохранения точности ПСД."""
        if value is None:
            return None
        if isinstance(value, float):
            raise TypeError("Использование float недопустимо. Передайте str или Decimal.")
        if isinstance(value, (int, str)):
            sanitized = str(value).replace(" ", "").replace(",", ".").strip()
            return Decimal(sanitized)
        if isinstance(value, Decimal):
            return value
        raise ValueError(f"Невозможно привести {value} к Decimal.")

class DiscrepancyReportItem(BaseModel):
    """Модель зафиксированной стоимостной или объемной коллизии."""
    model_config = ConfigDict(arbitrary_types_allowed=True)
    collision_type: Literal[
        "VOLUME_OVERRUN",      # Прямое превышение объема
        "MULTIPLIER_ERROR",    # Ошибка кратности (10, 100, 1000)
        "INCOMPATIBLE_UNITS",  # Конфликт физических размерностей
        "DUPLICATE_RESOURCE",  # Задвоение ресурса в смете
        "CABLE_SLACK_ANOMALY"  # Аномальный запас кабеля (>8%)
    ]
    severity: Literal["CRITICAL", "WARNING", "INFO"]
    spec_pointer: CellPointer
    estimate_pointer: CellPointer
    spec_qty: Decimal
    normalized_est_qty: Decimal
    delta: Decimal
    message: str
~~~

## 5. Алгоритмический конвейер сопоставления (MEP Tuning)

### 5.1. Инженерный фильтр габаритов (Dimensional Lock для ЭОМ/СС)
Введен дополнительный слой регулярных выражений для блокировки ложных срабатываний между схожими марками кабелей и автоматов.

* **Паттерн сечения кабеля:** `(?:\d+\s*[хxX*]\s*\d+(?:[.,]\d+)?)` 
  * *Срабатывание:* Извлекает `3х1.5`, `5x6`, `4*25`.
  * *Логика:* Если спецификация требует «Кабель ВВГнг-LS 3х1.5», а в смете указан «3х2.5», текстовая схожесть составит $>95\%$, но $\mathbb{I}_{\text{dim}}$ установится в $0$, предотвращая ложный мэтч.
* **Паттерн номинала автоматов:** `(?:\b\d+\s*(?:А|A)\b)` (например, `16А`, `32А`).

### 5.2. Матрица нормализации единиц измерения (Дополнение)

| Класс размерности | Каноническая единица | Допустимые входящие варианты (`raw_unit`) | Множитель приведения (`unit_multiplier`) |
| :--- | :--- | :--- | :--- |
| **Длина кабеля** | м | м, м.п. | Decimal("1.0") |
| | | 100 м, 100м | Decimal("100.0") |
| | | 1000 м, 1 км, км | Decimal("1000.0") |
| **Комплектация** | шт | шт, шт., штук | Decimal("1.0") |
| | | 100 шт, 100шт | Decimal("100.0") |
| | | компл, узел, система | Decimal("1.0") *(требует парсинга состава)* |

## 6. Краевые случаи ЭОМ и СС (MEP Edge Cases)

| Аномалия ЭОМ/СС | В чем выражается физически | Программная обработка в пайплайне |
| :--- | :--- | :--- |
| **Нормативный запас кабеля (Cable Slack)** | В спецификации указана точная строительная длина (например, 100 м), а в смете заложен запас на разделку, изгибы и отходы (102–106 м). | Вычисляется отношение: $R = \frac{V_{\text{est}}}{V_{\text{spec}}}$. Если $R \in [1.02; 1.06]$, коллизия подавляется (статус `INFO`). Если $R > 1.06$, фиксируется `CABLE_SLACK_ANOMALY` (`WARNING`). |
| **Комплектация vs Розница** | Проектировщик заложил «Шкаф серверный (комплект)», а сметчик расценил его по деталям: стойка, патч-панели, ИБП, органайзеры. | Если строка спецификации имеет ед. изм. `компл`, запускается алгоритм *Grouped Matching*: суммарная стоимость деталей сметы сопоставляется с лимитом на комплект (переход от объемного аудита к стоимостному). |
| **Скрытая гофра и крепеж** | Труба гофрированная и дюбель-хомуты «сидят» внутри комплексной расценки ФЕРм 08, но вынесены отдельно в ВОР. | Векторная проверка ресурсной части (как с `DUPLICATE_RESOURCE`). Если расценка включает ресурс «Трубы гибкие гофрированные», отдельная строка в смете маркируется как задвоение. |

## 7. Расчет финансового риска (Budget Risk Value)

Для оценки предотвращенного перерасхода при завышении длин кабельных трасс или задвоении комплектующих используется формула:
$$\Delta B = \sum_{i \in \text{OVERRUN}} (V_{\text{est}, i} - V_{\text{spec}, i}) \cdot C_{\text{unit}, i}$$
